# Stage Manager 1.0 compatibility

Stage Manager 1.0 replaces the Outliner+ 0.x scene-state model with canonical virtual-layer
paths, explicit state selection and participation, structural inheritance
boundaries, and separate local and effective item properties.

The old model cannot be converted unambiguously. In particular, 0.x used
rendered transparency both as a property and as an implicit state-selection
signal, so an automatic migration could mistake an effective override for a
user's local intent.

For safety, Stage Manager uses the `com.ex-asperis.obr-stage-manager/v1` namespace for virtual-layer
definitions, item assignments, item inheritance, temporary transparency state,
and temporary local-property shadows. Its scene document has schema version 3.
Metadata under the previous Outliner+ `com.ex-asperis.outliner` keys is left untouched and
is never partially applied by Stage Manager.

Scenes created by Outliner+ 1.0 use the same schema under the former
`com.ex-asperis.outliner/v1` namespace. Stage Manager offers a one-time conversion
for those scenes that copies the scene document, item metadata, and minimized
layout to `com.ex-asperis.obr-stage-manager` keys. The original keys are retained
as a fallback. The same conversion is available for beta-era schema-version-2
documents under the unversioned namespace; they are promoted to schema version
3 during the copy. Schema-version-1 data remains owned by the non-beta Outliner+
extension and is never copied or modified by Stage Manager.

Some schema-version-2 scenes predate explicit state selections and represent
suppressed state-linked layers as direct transparency. On the first selection
within such a group, Stage Manager reclassifies that group's stored transparency
as structural suppression so the selected state can be restored normally.

When a scene contains a 0.x virtual-layer document but no 1.0 document, the
Stage Manager displays a compatibility warning and starts with an empty 1.0 model.
Recreate the virtual layers and assignments in 1.0. Ordinary Owlbear item
properties remain authoritative unless a new 1.0 rule is actively overriding
them.

A malformed 1.0 scene-document header or unsupported schema version is rejected
as a whole. Stage Manager shows an error and applies no virtual-layer,
inheritance, or participation rules until the invalid scene document is
replaced.

Historical versioned manifests such as `manifest-v0.4.4.json` remain unchanged.
